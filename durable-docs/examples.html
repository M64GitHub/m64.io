Examples

Every idea in these docs has a runnable program behind it — a small workflow plus the worker and client that drive it, printing what it did. They come in both languages: TypeScript in examples/, Python in python/examples/, the same scenario on either side so you can read them against each other.

#Running one

Every example needs a local NATS with JetStream, and nothing else. The model calls in the AI examples are stubbed, so they run offline with no API keys.

sh
nats-server -js &

# TypeScript — from the repo root
NATS_URL=nats://127.0.0.1:4222 npm run example:charge

# Python — from python/
NATS_URL=nats://127.0.0.1:4222 uv run python examples/charge.py

The one to run first is crash → replay, in two commands — it is the whole idea in fifteen seconds. Phase 1 runs two steps and dies; phase 2 is a fresh process that replays them from the journal without re-executing them, and finishes the third:

sh
# phase 1 — two steps run, then the worker dies before the third
CRASH=1 DE_RUN_ID=crash-demo NATS_URL=nats://127.0.0.1:4222 npm run example:crash-replay
# phase 2 — a FRESH process picks the run back up
        DE_RUN_ID=crash-demo NATS_URL=nats://127.0.0.1:4222 npm run example:crash-replay

The Python twin is the same two commands against python/examples/crash_replay.py. There is a walkthrough of that run, with the dashboard alongside.

The workflow names are the same in both SDKs, deliberately: a Python worker and a TypeScript worker registered for saga share one work queue and one journal format, so either can drive the other's run. Only the fixed demo run IDs differ — the Python ones carry a py- prefix, so seeding one language's demo cannot collide with the other's.

#Correctness & failure

The four that show what the library actually promises, including where the promise stops.

ExampleWhat it showsSource
crash-replayKill a worker mid-run; a fresh one resumes from the journal and never re-executes a completed step.ts · py
recoveryThe three everyday failure modes: a raise that fails the run terminally, a flaky step an inline retry recovers, and a wait that runs out of time into a fallback.ts · py
exactly-onceThe guarantee and its caveat — an effect that fires twice across a crash, both times under the same ctx.key(). Exactly-once state, at-least-once effects.ts · py
determinismWhat breaks replay — a step renamed under a run already in flight — and the loud, terminal error that catches it instead of corrupting the run.ts · py

#Real-world patterns

ExampleWhat it showsSource
sagaA distributed transaction whose compensations run in reverse on failure — and because each undo is itself a durable step, the rollback is as crash-safe as the forward path.ts · py
approvalHuman-in-the-loop: an awaited signal with a timeout-escalation chain, plus a client-only CLI that sends the signal — the same thing the dashboard's button does.ts · py
ai-image-reviewGenerate an image, then regenerate until a human approves — driven from the dashboard or from the CLI. Each attempt is billed exactly once.ts · py

fan-outSeveral sub-workflows started in one pass and gathered with the language's own primitive, plus a race against a durable timer.ts · py

checkoutThe capstone. Steps, an awaited signal, a timer, a sub-workflow whose failure propagates back, and a saga unwind — in one workflow.ts · py

#Durable agents

A tool-calling agent's loop is a durable workflow: every model turn and every tool call is a journaled step, and a dangerous tool parks on a human-approval signal before it runs. Crash mid-task and the whole loop replays — the model is never re-called and never re-billed, and an effect never fires twice. Each is a real agent you can prompt over NATS, and the approval can be answered in the chat or in the dashboard.

ExampleWhat it showsSource
SRE assistantRead metrics, restart an unhealthy service (human-approved), post a note. The crash demo resumes without re-reasoning and without a second restart.ts · py
Coding agentRead, write, grep and run shell commands in a sandboxed workspace, with every command human-approved. The crash demo resumes without rewriting the file.ts · py

Two more live in the TypeScript tree only, because they exist to populate the dashboard for the walkthroughs rather than to teach: seed-demo and fanout-cancel-demo. Both READMEs — TypeScript · Python — say what each one teaches in more detail.
